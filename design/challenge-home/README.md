# 挑战首页重构设计稿

## 交付文件

- `challenge-home-standard.png`：标准竖屏基准，目标视口比例 390 × 844。
- `challenge-home-compact.png`：紧凑短屏基准，目标视口比例 347 × 602。

两张稿件使用同一套视觉语言和交互结构，差异只来自可用高度，不是两套独立页面。

## 页面结构

1. 顶部品牌区固定：完整展示“抓住大鹅”，设置与声音入口保持在右上角。
2. 中部地图为独立纵向视口：地图可滚动，路线从顶部继续延伸，后续章节按同一规格向上追加。
3. 底部挑战控制台固定并占据真实布局空间，不再作为覆盖层压在地图或信息上。
4. 控制台内容顺序固定：关卡摘要 → 难度 → 场景固定提示 → 出发挑战 → 今日剩余。

## 响应式规则

- 页面内容最大宽度 720 设计像素；超宽屏整体居中，左右只展示背景延展。
- 标准模式优先保留地图展示面积和完整装饰间距。
- 紧凑模式先压缩装饰留白、地图可视高度和控件间距，不隐藏关卡摘要、难度、提示、主按钮或次数。
- 底部控制台高度必须计入地图视口计算；禁止复制一个悬浮 CTA 作为短屏兜底。
- 主按钮与底部次数之间保留安全区，兼容设备底部安全边距。

## 实现约束

- 地图、顶部品牌区、底部控制台必须是三个独立节点层级。
- 地图选择变化只刷新地图选中态与摘要，不重建固定控制台。
- 难度选择同理：只切三张切图的透明度、挪选中辉光、改摘要与成绩行。
  回 `GameManager.showHome()` 重建整页会连地图一起淡入淡出，看起来就是「点一下闪一下」。
- 三张难度切图 `difficulty-{easy,normal,master}-clean.png` 是各自独立生成的，
  画布高度（368/334/322）和内部元素大小都不一致：必须按各自比例铺开、再按内容中心对齐，
  不能统一拉成同一个高度（旧实现拉成 600×170，easy 压扁 7.6%、master 拉高 5.6%，
  每次换档整条难度条都在缩放跳动）。对齐参数见 `HomeScreen.DIFFICULTY_ART`。
- 三档热区中心为 ±242 / 0（由切图量出），不是早期手写的 ±220。
- 打开页面时自动将当前地图节点滚动到地图视口的视觉中心。
- 新地图只追加地图章节数据和对应美术段，不修改底部控制台布局。
- 设置、声音、地图节点、难度和出发按钮必须保留独立触控热区。

## 生成说明

- 工具：内置 Image Gen。

- 紧凑稿提示重点：保持标准稿结构与内容，在 347 × 602 比例内压缩留白和地图高度，所有五层底部信息保持完整且互不遮挡。
